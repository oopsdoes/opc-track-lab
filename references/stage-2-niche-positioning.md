# 阶段 2 · 利基定位（赛道推演核心）

> 蒸馏自 easychen/opc-methodology 官方技能 `opc-niche-positioning`（SKILL.md + market-scan-checklist、niche-evaluation、positioning-formula）与书中「赛道选择」一章（详见 track-selection.md），中文改写版（2026-10）。冲突时以官方为准。

## 目标

帮用户从宽方向收敛到一个值得投入的细分入口：**四问快筛 → 三环深挖 → 六维评分 → 确认定位陈述**。

## 边界

**只做**：赛道分析、候选利基生成与评分、定位陈述。
**不做**（出现即拉回）："发什么内容/怎么写文案/怎么发小红书" → MVP 或转化阶段；"产品定价" → 阶段 4；获客路径细节 → 阶段 6。
话术："这个方向很有价值，不过它属于后续 [X] 阶段的范围。我们先把利基定位确认好，后面的执行才有准确的靶心。"

## 第 0 步：找方向（仅在用户说不出候选方向时）

三武器分工（详见 case-source-guide.md）：

- **用户说不出任何候选方向** → 用 **Awesome 方向地图**：`python scripts/gh-fetch.py awesome [感兴趣的关键词]`，翻活跃生态给用户看，聊出 2~3 个宽方向
- **有宽方向后** → 用 **1c7 案例库找同类**：`python scripts/gsh-fetch.py cases --track <关键词>`，看别人在这个赛道做了什么（找同类、找空白、避红海）
- **发现值得深读的开源同类** → 给出 Zread.ai 链接（github.com 换成 zread.ai）

案例库查无此领域（如线下生意）→ 走"域外处理"（文末），**流程照常，不阻塞**。

## 第一层：四问快筛（书中框架，把宽方向收窄成 2~4 个候选赛道）

对每个宽方向过四问，每问给"通过/不通过 + 一句话理由"。**判断纪律（Jev 式小脑）：理由必须绑定证据**——引用资源清单第 X 项、案例库条目（名+抓取日期）或用户原话；没有证据就写"信息不足，需访谈补充"，禁止无依据下结论：

1. **是不是小众刚需？** 远离大众刚需——找"大众的弱需求、小众的强需求"；仍拥挤就继续细分
2. **有没有触达能力？** 能否低成本聚集这群人（内容营销 / SEO / SideProject 营销 / 已有渠道）
3. **是不是专长领域？** 不用顶尖，但要有"收益不高也愿意持续投入"的热情
4. **列赛道清单**：通过的都列出来，不要只想到一个就押注

被四问毙掉的方向如实说"为什么被毙"，用户坚持可保留进入下一层（标注风险）。

## 第二层：三环合一（对候选赛道深挖）

执行顺序：**先环 2 → 再环 1 → 最后叠环 3**。

### 环 2：边界变动（从行业变化开始，不从用户需求开始）

扫描三类变动：
- **技术边界**：AI 或新技术让什么变得可能？过去十人团队的事现在一人能做吗？
- **信息传播路径变动**：目标用户最活跃在哪些平台？有没有"流量已到、商业化未饱和"的窗口？
- **政策/监管变动**：有没有政策正在推动某个细分、或压制大公司扩张？

**核心判断：大公司能追吗？**——原有路径上的受益者为什么不追？（价值网络冲突 / 初期利润太低看不上 / 沉没成本太高重建不动）能回答出来，才是以小博大的空间。

### 环 1：新杠杆与元杠杆

- **代码杠杆**：一次构建无限服务（软件/工具/自动化），服务第 100 万和第 101 个用户成本几乎为零
- **媒体杠杆**：一次诉说无限回响（文章/视频/播客），睡觉时也在工作
- **元杠杆（AI）**：杠杆的杠杆——哪些工作流过去要团队、现在一人+AI 就能做？有没有完整业务闭环可以自动运转（无人监督时自动采集/创作/发布/迭代），创始人从驾驶员变调度员？大公司有流程包袱，一人公司反而灵活——速度差在哪？

每个环问自己：这个赛道能不能用代码或媒体作为主要交付形式，而不是人力一对一？

### 环 3：独有资源和优势

**直接读 `opc-doc/outputs/01-resource-audit/inventory.md`，不重新收集。** 把环 1+2 的发现叠在资源盘点上，找三环重叠区。只靠资源匹配（仅环 3）的竞争优势最弱。

市场扫描补充清单（至少回答）：当前市场主要问题？现有替代方案？为什么仍不满足一部分用户？最近的边界变动是什么？是否给一人公司创造了切口？

## 第三层：六维机会评分（1~5 分/维，满分 30）

| 维度 | 评估内容 |
|------|----------|
| 痛点强度 | 是忍一忍就过去的不便，还是反复影响核心需求？ |
| 杠杆密度 | 代码、媒体、AI 自动化有几种能同时叠加？ |
| 窗口红利 | 时间窗口多宽？现在进入是不是边界移动早期？ |
| 资源匹配度 | 现有资源有多少可直接转化为优势？ |
| 交付标准化程度 | 能否形成可复用交付流程，而不是每次从头定制？ |
| 现金流潜力 | 不依赖大量前期资本，多快能产生实际收入？ |

⚠️ 评分只作**相对参考**（用于候选间比较），不当真理。**每维打分必须跟一句话依据**（引用资源项/案例条目/用户原话），拿不出依据的维度标"待补"且不计入总分。

**本节点走 Jev 判断关**：AI 初判后生成考卷（opc-doc/judge/）跑 `python scripts/jev-check.py` 复判，向用户呈现双列对照表（AI 初判｜Jev 判定｜分歧标记），分歧项（分差≥2）用户终判；未配置判卷模型时标注「单阅卷」继续。出题与分歧规则见 judgment-protocol.md。

## 候选呈现格式（生成 3 个候选 + "4. 我有自己的方案"）

```
候选利基 X：[简短名称]
目标用户：谁，处于什么处境
核心痛点：什么问题，有多痛
激活的环：✅/❌ 环1（新/元杠杆）| ✅/❌ 环2（边界变动）| ✅/❌ 环3（资源匹配）
时间窗口：为什么是现在，窗口还有多宽
大公司为什么不来：价值网络冲突 / 体量太小 / 速度太慢
案例库同类参照：[有则列 3~5 个：项目名+一句话+状态+版面+抓取日期；无则注明"案例库无此领域，已走域外处理"]
机会评分：痛点 X | 杠杆 X | 窗口 X | 资源匹配 X | 标准化 X | 现金流 X → 总分 XX/30
风险点：
判断置信度：高/中/低（低=证据缺口清单：还差哪些信息）
```

优先推三环都激活、总分最高的；两环次之；仅环 3 的作保底不主推。**只给分析不给结论性推荐**，用户确认后落盘。

## 定位陈述（用户确认主利基后生成）

> "我为【目标细分用户】提供【核心结果】，区别于【替代方案】，我的优势是【独特资源/方法/视角】。"

## 异常处理

- 市场太大 → 强制继续切细，不停留在宽泛市场
- 用户给不出答案 → 基于行业背景生成合理候选供判断，不把压力全丢给用户
- 三环找不到重叠点 → 如实告知，探讨扩大行业范围或调整资源方向
- 域外赛道 → 见下

## 域外赛道处理（硬规矩，如线下摆摊）

1. 案例库（1c7）只覆盖网站/App 类项目——查无此领域时**第一句话明说**："案例库不覆盖这个领域，这不影响推演，四问和三环本身领域无关。"
2. **禁止**把问题硬掰到库内案例上（禁止"问摆摊答工具站"式强行类比）
3. 可用**结构类比**（如"选址=流量入口，复购=触达"），必须标注："跨域参照，低置信度，仅供思路"
4. **反向访谈**：用户的一线经验比案例库值钱——"你比案例库懂这行，这个领域里谁在赚钱、谁在赔钱，你看到的现状是什么？"
5. 案例环节优雅跳过，四问/三环/六维照常走完

## 落盘检查点（用户确认后立即执行）

1. `opc-doc/outputs/02-niche-positioning/three-ring-analysis.md` — 可用杠杆清单、边界变动清单、资源重叠识别
2. `opc-doc/outputs/02-niche-positioning/candidates.md` — 3 个候选及六维明细
3. `opc-doc/outputs/02-niche-positioning/target-segment.json` — `{"segment":"...","core_pain":"...","timing":"...","rings_activated":["leverage","boundary_shift","resource_match"],"opportunity_score":{"pain":0,"leverage":0,"window":0,"resource_fit":0,"standardization":0,"cashflow":0,"total":0},"why_viable":"...","why_big_players_wont":"..."}`
4. `opc-doc/outputs/02-niche-positioning/positioning-statement.md` — 定位陈述
5. `opc-doc/state/current-stage.json` → `{"stage":"02-niche-positioning","status":"completed","next_stage":"03-value-proposition","summary":"一句话定位核心"}`；`decisions.json` 追加利基选择

落盘后告知："✅ 利基定位结论已保存。下次对话可以从价值主张继续。"

## 完成标准

- [ ] 四问快筛完成（被毙方向有理由）
- [ ] 三环分析完成（环2→环1→环3 顺序）
- [ ] 3 个候选含六维评分（或域外走完等效分析）
- [ ] 用户确认主利基 + 定位陈述已生成
- [ ] 已落盘
