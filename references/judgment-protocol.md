# Jev 判断关协议（判卷手册）

> 定位：把流程里"赌注大、AI 自判易偏"的判断节点，改造成 Jev 式三段——**AI 出题 → 判卷模型只判不写 → AI 对答案呈现给用户**。判卷结果（Jev 给的判断和分数）必须出现在用户看到的内容里。

## 分工铁律

| 角色 | 干什么 | 绝不干什么 |
|------|--------|-----------|
| AI（出题人） | 从 opc-doc 组装精简材料、按固定判据出题、对答案、生成解释 | 不替用户终判；不在题目里夹私货；材料不足不硬判 |
| 判卷模型（阅卷员） | 依据给定材料，只返回裸分数/选项 | 不解释、不创作、不使用材料外知识、不决策 |
| 用户（终判人） | 看双列对照，分歧项拍板 | —— |

## 常设节点

| 节点 | 考卷材料来源（全部现成，不重新收集） |
|------|--------------------------------------|
| 阶段2·四问快筛 | inventory.md（资源清单）+ track-selection.md 判据 + 案例切片 + 用户原话 |
| 阶段2·六维评分 | scorecard.json + candidates 素材 + 案例切片 + 用户原话 |
| 阶段5·MVP 到期验收 | experiment-plan.md 的成功标准 + 用户提供的执行数据 |
| 阶段6·复盘诊断 | conversion-path.md + MVP 验收记录 + 用户口述经营现状 |
| 拆项目模式 | 项目材料 + 四问判据 + （可选）案例库同类切片 |

豁免：日常对话轻判断、确认类问题、阶段1（纯收集）、阶段3（创作）。批量案例匹配（判卷模型逐条扫全库找同类）→ V2。

## 考卷格式（AI 生成，JSON 文件，存工作目录 opc-doc/judge/）

```json
{
  "title": "候选赛道六维评分复判",
  "state": "只放判题所需事实：资源要点、案例条目（名+状态+抓取日期）、用户原话。缺材料先标待补，不硬判",
  "questions": [
    {"id": "niche-ok", "type": "noul",  "ask": "是否为小众刚需？",
     "criteria_true": "大众弱需求但该人群强需求", "criteria_false": "大众刚需红海"},
    {"id": "best",     "type": "choice", "options": ["A", "B", "C"], "ask": "资源匹配最高的是"},
    {"id": "A-pain",   "type": "score",  "scale": [1, 5], "ask": "候选赛道A痛点强度"}
  ]
}
```

三种题型：**noul**（是/否概率，四问快筛用）、**choice**（选项，比较类判断用）、**score**（量表，六维评分用）。出题规矩：题干引用固定判据原文；一个维度一题；材料里没有支撑的维度不出题（标"待补"）。

## 判卷与降级

```
python scripts/jev-check.py opc-doc/judge/<考卷>.json
```

- 配置了 `OPC_JUDGE_BASE_URL` / `OPC_JUDGE_API_KEY` / `OPC_JUDGE_MODEL` → **双阅卷**，协议自动识别（可 OPC_JUDGE_API 强制指定）：
  - **decisions 协议**（OpenRouter 上的 Jev，typesafe/jev-*）：走原生 `/api/alpha/decisions`，返回校准概率。**2026-10-02 实测通过**（noul 0.84→是、choice 正确、score 为量表连续位置如 2.1≈"2 分"档，卡片上由 AI 标注档位）
  - **chat 协议**（千问 DashScope / 豆包方舟 / 智谱 / 本地 Laya 网关等 OpenAI 兼容接口）：严格系统提示（只答题号和答案、禁解释）+ 温度 0 模拟判卷纪律
- 未配置或调用失败 → **单阅卷**：AI 按同一考卷自判，卡片标注「单阅卷」，流程永不阻塞
- 判卷模型温度固定 0；它返回的裸结果原样采用，**禁止替它改分**；AI 的解释必须标注「AI 解读」

```
📋 判断卡片 · 六维评分（双阅卷，判卷模型: qwen-flash）
维度         AI初判   Jev判定   分歧   依据
痛点强度     4        4         一致   案例库3条同类均在持续迭代（抓取2026-10-02）
杠杆密度     5        3         ⚠️分歧 AI解读：…｜分歧原因待议
资源匹配     3        待补               scorecard 第2类资源信息不足
把握度：高×4 / 中×1
→ 分歧项与待补项请你终判或补材料，其余进入下一节点
```

## 分歧处理规则

1. 分数题分差 ≥2、或选择题选项不同 → 标 ⚠️，AI 给出两边可能成立的理由（标注 AI 解读），交用户终判
2. 用户终判结果为准，落盘时记录三方（AI/判卷模型/用户）意见，写入对应 outputs 文件
3. 「待补」项不许悄悄放过——要么补材料重判，要么在定位陈述/MVP 标准里显式降级为假设

## 禁止事项

1. 禁止编造 Jev 的判定（没跑脚本就说"Jev 判了 4 分"是造假）
2. 禁止让判卷模型写理由、写文案、做决定
3. 禁止把用户的终判说成"Jev 认为对"
4. 轻判断不得强行上判断关（仪式税）
